# Handoff: FirstCall Capability Explorer

## Overview
An interactive "Capability Explorer" section for firstcallgroup.com. It presents an
illustrated isometric city district where each building represents an industry vertical
FirstCall serves (Commercial, Healthcare, Data Centers, Education, Higher Ed, Hospitality,
Government, Multifamily, Industrial). Visitors filter by industry, click a building to open
a side panel describing why those facilities are demanding and which FirstCall capabilities
serve them, click rooftop equipment for coverage tooltips, and submit a "Talk to FirstCall"
contact form.

## About the Design Files
The files in `source/` are a **design reference created in HTML** — a working prototype that
shows the intended look, content, and behavior. They are **not** meant to be shipped verbatim
into production. The task is to **recreate this design inside firstcallgroup.com's existing
front-end environment**, using its established framework, component patterns, and build
pipeline. If the site has no component framework (e.g. it's a CMS/WordPress/static theme),
embed it as a self-contained widget (see "Integration options" below).

The prototype is built with React 18 + JSX, currently transpiled in-browser by Babel and
loaded from a CDN. That in-browser compile step is fine for a prototype but should be removed
for production (pre-compile the JSX at build time).

## Fidelity
**High-fidelity.** Colors, typography, spacing, copy, and interactions are final and intended
to match the firstcallgroup.com brand. Recreate the UI faithfully. The isometric scene itself
is hand-built SVG generated by `scene.jsx` — reuse that code directly rather than redrawing it.

## Architecture (current prototype)
- `FirstCall Capability Explorer.html` — entry point. Loads Google Fonts, React/ReactDOM/Babel
  from unpkg, then the four scripts below. Mounts the app into `<div id="root">`.
- `data.js` — plain global script. Defines `window.FCG = { CAPS, EQUIP, BUILDINGS, FILTERS }`.
  **All editable content lives here** (vertical names, blurbs, stats, capability descriptions,
  equipment labels/specs). Non-developers can be pointed here to revise copy.
- `icons.jsx` — monoline icon set, exported as `window.Icons`.
- `scene.jsx` — the entire isometric district as SVG (buildings, equipment, roads, traffic,
  campus, monument, props). Exports `window.CityScene`. This is the largest file.
- `app.jsx` — the React app shell: header, filter pills, side panel, equipment tooltip,
  contact modal, keyboard/ARIA wiring, and state management. Renders `<CityScene>`.

`source/FirstCall Capability Explorer (standalone).html` is the same app fully inlined into one
offline file — useful as a visual reference or as a drop-in `<iframe>` if you choose Option 1.

## Integration options
1. **iframe embed (fastest):** drop `FirstCall Capability Explorer (standalone).html` onto the
   server and embed via `<iframe>` sized to the section. Zero build changes; the in-browser
   Babel compile (~0.5–1s) remains. Acceptable for a marketing section, not ideal for Core Web
   Vitals.
2. **Native React integration (recommended):** port the four scripts into the site's React
   build as real modules, pre-compiled at build time. Convert the `window.*` globals into ES
   module imports/exports. Mount `<App />` into the target container in the page template.
   This removes the CDN + Babel runtime and gives instant render.
3. **Web component / island:** if the site isn't React, wrap the compiled app as a single
   self-mounting bundle (one `<script>` + a mount `<div>`), built with esbuild/vite. The app
   already mounts into one root node, so this is straightforward.

## Screens / Views
This is a single-view interactive section. Sub-states:

### 1. Default scene
- **Purpose:** orient the visitor; invite exploration.
- **Layout:** centered header (eyebrow + headline + lead + stat line), centered filter pill row,
  then the full-width isometric SVG stage. On screens ≤760px the stage becomes horizontally
  swipeable and a "swipe to explore" hint appears.
- **Components:** 9 building hotspots (pulsing blue dots), 9 callout labels with dotted leader
  lines, ambient motion (8 vehicles + 1 transit bus, steam, blinking lights).

### 2. Building selected (filter pill OR building click OR callout click)
- The chosen building spotlights; the rest dim (`opacity .38`, slight grayscale).
- Its rooftop **equipment hotspots fade in** (progressive disclosure — hidden by default).
- A **side panel** slides in from the right (desktop) / up as a bottom sheet (≤760px) with:
  category eyebrow, building name, "why demanding" blurb, a stat, 3–4 capability cards
  (icon + name + description), a "Systems on site" chip row, and a "Get in Touch" CTA.

### 3. Equipment tooltip
- Clicking an equipment hotspot opens a small card near the cursor: equipment label, spec
  (mono), and which FirstCall capability covers it (dot + name).

### 4. Contact modal ("Get in Touch" / "Talk to FirstCall")
- Centered modal over a scrim. Fields: Name, Company, Work email, Facility type (prefilled from
  the building you came from), free-text "What do you need?". Submit shows an in-modal success
  state referencing the 24/7 dispatch line **844.715.0220**.
- **This form is currently a front-end demo — `onSubmit` only flips to the success state.**
  See "Functional work required."

## Interactions & Behavior
- Hover a building (or its callout) → spotlight it, dim others, reveal its equipment dots.
- Click a building / callout / filter pill → select it, open the side panel, sync the active
  filter pill. Filter "All" closes the panel.
- Click equipment → tooltip (closes on scroll, Esc, or its × button).
- Esc key closes, in priority order: modal → tooltip → panel.
- Panel/modal transitions: `transform .5s` and `.3s` on `cubic-bezier(.22,.61,.36,1)`.
- All motion is gated behind `@media (prefers-reduced-motion: no-preference)`.
- Traffic runs at uniform speed with phase offsets tuned so vehicles never collide at
  intersections — preserve the `TRAFFIC` array timing if you refactor.

## Accessibility
- Every hotspot is a `role="button"` with `tabIndex=0`, an `aria-label`, and Enter/Space
  activation. Preserve this. Callout labels are decorative (`aria-hidden`) since their building
  hotspot is already focusable.
- Side panel is a labelled `role="dialog"`; contact modal is `role="dialog" aria-modal="true"`.
- Focus is moved into the panel/modal on open. Maintain focus management when porting.
- Respect `prefers-reduced-motion` (already wired).

## State Management
React `useState` in `app.jsx`:
- `activeId` — currently selected building id (or null)
- `hovered` — hovered building id (drives spotlight/dim)
- `filter` — active industry pill
- `tip` — `{ eqId, x, y }` for the equipment tooltip (or null)
- `modal` — `{ open, context }` for the contact form
- `hintGone` — whether the mobile swipe hint has been dismissed
Derived: `spotlight = hovered || activeId`. No data fetching — all content is static in `data.js`.

- Ink `#182a1f`, body text `#56635a`, muted `#7d897f`

- Amber accent `#f5a623` (used sparingly — realistic hazard/safety details only)
Type:
- Headings: **Archivo** (700/800). Body: **IBM Plex Sans** (400–700). Mono labels: **IBM Plex Mono**.
- Section headline `clamp(28px, 3.6vw, 42px)`; body 14–15.5px; mono eyebrows ~11–12px, letter-spacing .2–.26em.
Radius: cards/inputs 9–12px, pills 999px, modal 16px.
Shadow: `0 16px 40px -16px rgba(24,42,31,.25)`.
Easing: `cubic-bezier(.22,.61,.36,1)`.
SVG scene palette (buildings) lives inline in `scene.jsx` per-building `body`/`glass`/`accent`.

## Assets
- **Fonts:** Google Fonts (Archivo, IBM Plex Sans, IBM Plex Mono). In production, self-host or
  load via your existing font pipeline.
- **No external images.** The FirstCall logo on the central monument is drawn as a pure SVG
  hexagon (no raster file). Earlier raster-logo experiments were removed; nothing in `source/`
  references an image file.
- **Icons:** all inline SVG in `icons.jsx`.
